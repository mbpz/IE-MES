# ERP 订单与交付数量入口重建

原仓库的 `ErpOrderController` 和 `DeliverNumberController` 只有 JSP 跳转；对应 JSP、数据表、API 与外部 ERP 连接均不存在。用户没有旧版备份，也无法确认原交互。本页记录本次重建的业务定义，不能当作旧系统行为的证明。

## 最小可运行流程

1. ERP 订单页手工登记外部订单号、客户、物料、数量、预计交付日，可选关联当前站点已有工单；同一站点的外部订单号不能重复。页面按当前站点查询记录。暂不声称接入外部 ERP，也不自动创建或下达 MES 工单。
2. 交付数量页选择当前站点工单，登记本次交付数量、单据号和备注，显示历史交付与累计数量。服务端在事务内锁定工单并核对累计交付不得超过工单数量；不同站点的工单不可提交。
3. 交付登记是独立台账，不扣库存、不修改 SFC 或工单生产状态。现有仓库没有成品出库和发运数据模型，页面明确标注这一边界。

## 数据与权限

- 新增 `ly_erp_order` 和 `ly_delivery_record`，以现有 `ly_shoporder.id` 关联工单，所有查询和写入按会话站点过滤。
- 新增两个菜单资源并授予现有管理员角色；其他角色可通过现有权限管理单独授权。新页面与 API 使用各自的资源键。
- 迁移 SQL 对新建数据库自动执行；已有 Docker 数据卷需先备份，再执行同一幂等迁移 SQL，最后重建应用。
